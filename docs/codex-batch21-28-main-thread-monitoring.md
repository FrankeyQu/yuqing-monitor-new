# Batch 21-28 主线程与子线程监控规则

每次进入新步骤、接收子线程结果或上下文恢复时，先读取：

```text
docs/codex-coordination-memory.md
```

## 1. 总原则

Batch 21-28 采用“主线程控盘、子线程执行局部任务”的方式推进。主线程负责方案、架构、合规、任务拆分、质量门禁、集成和最终验收；子线程只负责明确范围内的探索、实现或验证。

主线程不能把以下事项交给子线程自行决定：

- 产品方向。
- 数据模型主干。
- 权限和审计边界。
- 合规边界。
- 外部真实数据源接入。
- 密钥、账号、生产环境配置。
- 数据库不可逆变更。

## 3. 每个 Batch 的固定分工

### 3.1 方案子线程

用途：

- 只读分析现有代码。
- 给出方案约束、复用点、风险。

输出：

- 关键文件路径。
- 现有实现模式。
- 建议落点。
- 风险和不建议做的点。

禁止：

- 修改文件。
- 扩大需求。
- 引入新技术栈。

### 3.2 实施子线程

用途：

- 在主线程批准的文件范围内实现小模块。

输出：

- 修改文件列表。
- 核心实现说明。
- 自测结果。
- 未完成项。

禁止：

- 修改未授权文件。
- 重构无关代码。
- 修改旧迁移脚本。
- 接入真实密钥或真实生产账号。

### 3.3 验证子线程

用途：

- 编译、构建、接口检查、页面检查、SQL 检查。

输出：

- 验证命令。
- 验证结果。
- 问题列表。
- 建议修复方式。

禁止：

- 未授权修复。
- 跳过失败项直接标记通过。

## 4. 主线程质量门禁

每个 Batch 必须经过以下门禁：

1. 方案门禁：方案文档已形成，目标、不做范围、合规边界清楚。
2. 代码门禁：主线程审查所有子线程改动，确认没有越权修改。
3. 数据库门禁：只新增迁移，不随意修改旧迁移。
4. 安全门禁：无真实密钥、Cookie、账号、生产地址入库或入代码。
5. 权限门禁：新增菜单、接口和敏感操作有权限策略。
6. 审计门禁：关键配置、任务、运行、密钥引用操作有审计。
7. 构建门禁：后端 Maven 和前端 build 尽量执行，失败必须解释。
8. 验收门禁：给出手工验收路径和残余风险。

## 5. 子线程任务单格式

每次分派子线程必须包含：

```text
任务名称：

背景：

目标：

允许读取范围：

允许修改范围：

禁止事项：

必须遵循的现有风格：

交付物：

验证要求：
```

如果是探索子线程，允许修改范围必须写为“无，只读”。

## 7. 到 Batch 28 的推进策略

每个 Batch 采用同样节奏：

```text
方案 V0.1
  -> 子线程只读摸底
  -> 方案 V0.2
  -> 主线程自审
  -> 必要时用户确认
  -> 实施子线程小范围开发
  -> 主线程审查集成
  -> 验证子线程或主线程验证
  -> 更新控制台
```

如果某批方案没有打磨清楚，主线程不得为了进度强行进入编码。

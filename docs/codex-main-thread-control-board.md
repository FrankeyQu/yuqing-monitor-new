# Codex 主线程控制台：Batch 11-32

## 1. 主线程职责声明

从 Batch 11 到 Batch 32，Codex 主线程负责持续控盘、监控进度、做技术决策、保持合规边界，并把系统推进到可试运行、可扩展接入、可验收交付状态。

主线程不是单纯执行代码修改，而是承担以下职责：

- 判断下一步应该做什么。
- 拆分每个 Batch 的最小可交付闭环。
- 控制数据库迁移、后端接口、前端页面、权限审计之间的顺序。
- 决定哪些问题立即修，哪些进入后续批次。
- 发现偏离校园业务目标时主动纠偏。
- 每批结束后更新状态、运行验证、记录风险。

Batch 21-28 的子线程分工、任务单、质量门禁和监控规则见：


## 2. 主线程决策权限

主线程可以直接决策：

- Batch 内部任务顺序。
- 表结构字段的常规命名和索引设计。
- Controller、Service、Mapper 的落点。
- 前端目录结构、组件拆分、接口封装方式。
- 页面筛选项、表格列、基础交互。
- 本地开发脚本、校验脚本、演示数据脚本。
- 不改变产品方向的小型修复。

主线程必须向用户确认：

- 是否引入新的大型技术栈。
- 是否删除旧功能或旧页面。
- 是否重置数据库或清空数据。
- 是否改动登录认证主流程。
- 是否改变合规边界。
- 是否接入外部模型、外部采集源或真实生产账号。
- 是否做不可逆部署操作。

## 5. 每批固定执行流程

每个 Batch 必须按以下顺序推进：

1. 进入方案打磨态，先输出本批详细实施方案和技术方案。
2. 明确本批目标、不做什么、合规边界、验收口径。
3. 阅读相关已有代码和接口，确认复用点和冲突点。
4. 拆分数据库、后端、前端、脚本、文档任务。
5. 对技术方案做至少一轮自审，重点检查数据模型、接口边界、权限审计、可回滚性和后续扩展性。
6. 如涉及外部数据接入、真实账号、合规边界、大型技术栈或不可逆操作，必须等用户确认后再实施。
7. 检查 `git status`，确认是否有无关改动。
8. 实施最小闭环。
9. 运行必要验证。
10. 修复验证中发现的问题。
11. 更新本控制台和拆分清单。
12. 汇报完成内容、验证结果、剩余风险、下一批建议。

## 5.1 方案打磨闸门

从 Batch 21 起，每个 Batch 必须先形成独立方案文档，默认命名：

```text
docs/batchNN-<module-name>-plan.md
```

方案文档必须包含：

- 背景和本批目标。
- 明确不做的范围。
- 数据流和模块边界。
- 数据库变更方案。
- 后端接口和 Service 设计。
- 前端页面和交互设计。
- 权限、审计、合规约束。
- 失败、重试、幂等、去重策略。
- 验收步骤。
- 风险和待确认问题。

主线程在方案未完成前不得直接进入代码实现。方案完成后状态为 `Plan Review`；通过后才进入 `In Progress`。

## 6. 每批验证闸门

### 后端 Batch

必须尽量执行：

```powershell
.\mvnw.cmd -DskipTests package
```

必须检查：

- Flyway 迁移可执行。
- Mapper XML 可解析。
- 关键接口未登录拦截行为符合预期。
- 新增接口返回结构统一。
- 关键操作写审计。

### 前端 Batch

必须尽量执行：

```powershell
npm run build
```

必须检查：

- 页面无明显布局错乱。
- API 错误有提示。
- 登录态丢失能回登录页。
- 表格、筛选、分页、详情、弹窗基本可用。
- 页面文案校园化，不出现旧产品无关品牌内容。

### 联调 Batch

必须跑通：

```text
接入记录 -> 检测命中 -> 自动预警 -> 人工研判 -> 转事件 -> 分派处置 -> 部门反馈 -> 复核归档 -> 生成报告
```

## 7. 阻塞处理规则

环境阻塞：

- 优先用本地免安装工具解决。
- 不能解决时写入运行手册，不让问题散落在聊天里。

编译阻塞：

- 主线程直接定位和修复。
- 不跳过编译错误进入下一批。

需求阻塞：

- 对非关键选择，主线程做保守决策。
- 对合规、权限、产品方向、真实数据接入，必须等用户确认。

旧系统冲突：

- 新校园能力优先放在 `campus` 命名空间。
- 不破坏旧接口和旧页面。
- 如需替换旧能力，先提供兼容过渡方案。

## 8. 合规决策准则

任何批次都必须遵循：

- 只处理公开、授权、上级移交、学校业务中依法获得的数据。
- 不设计绕过平台限制、破解登录、批量撞库、私信采集能力。
- 不自动识别学生私人账号。
- 重点账号必须有来源依据、任务编号、授权范围、关注期限、审核记录。
- 检测命中不等于事件结论，必须经过人工研判。
- AI 分析只作为辅助建议。

## 9. 主线程默认推进顺序

默认不再反复询问是否开始下一批。当前批完成并通过验收后，主线程自动建议并准备下一批。

默认推进顺序：

```text
Batch 21 -> Batch 22 -> Batch 23 -> Batch 24 -> Batch 25 -> Batch 26 -> Batch 27 -> Batch 28 -> Batch 29 -> Batch 30 -> Batch 31
```

如果中途发现前置能力缺失，主线程可以插入小批次修复，但必须记录：

- 插入原因
- 修改范围
- 是否影响原计划
- 验证结果
